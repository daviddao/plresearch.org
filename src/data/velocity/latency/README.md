# Latency-compression CSVs

One CSV per focus area for the **latency compression** instrument on `/impact`:
the lag between two stages of a field's pipeline, and whether it is shrinking.
Each field measures a different pipeline, so the generators differ, but the CSV
shape and the honesty rules match the idea-vintage pipeline in the parent
directory: real data only, provenance in leading `#` lines, recent years flagged
`reliable=0`, and an absent file is the correct empty state (the instrument
stays `unwired`).

## AI & Robotics — paper → open-weights implementation

`ai-robotics.csv`, generated by
[`scripts/velocity/latency_pwc.py`](../../../scripts/velocity/latency_pwc.py).

Metric: median days from a paper's arXiv publication to the first commit of a
linked open-source implementation, per publication year. Historical spine is the
Papers With Code paper↔code link dataset (CC-BY-SA, archived July 2025), joined
to arXiv publication dates and GitHub first-commit dates. The series ends in
mid-2025 by construction (the archive freeze); the last year or two are
unreliable because a recent paper's implementations are still landing.

```
year,median_lag_days,lag_ci_lo,lag_ci_hi,n_papers,reliable
2018,120,95,150,220,1
...
```

- `median_lag_days` drives the series; a **falling** lag means the field is
  turning papers into working code faster, i.e. accelerating.
- `lag_ci_lo/hi` is a **cluster bootstrap** that resamples papers (a paper is the
  unit; one paper may link several repos), not individual repos.
- `reliable=0` marks recent years still filling in; excluded from any trend.

> **Status: `unwired`.** The generator exists; the CSV does not yet. Running it
> needs the archived PWC links file on disk (`--links`) and, for a full run,
> a `GITHUB_TOKEN` to lift the GitHub API rate limit. Until then the AI &
> Robotics latency record stays an honest `unwired` in
> `src/lib/velocity-instruments.ts`.
